# Source update history

`updates.jsonl` is generated by the repository workflow after eligible pushes. Each line is metadata about a source update, not a runtime log or visitor record. It must never include `.env`, sessions, message contents, phone numbers, IP addresses, cookies, or API credentials.

Website page views belong to the website's analytics implementation. See the archived analytics and audit documentation in the repository documentation archive.

## Documentation contract (2026-10-25)

For each feature addition, fix, change, or removal: add a dated record under `docs/`, update the links at `docs/README.md`, and append/update the relevant root `README.md` section without deleting unrelated existing content. Include Mermaid architecture maps for significant cross-module changes and a test report that separates tests actually run from checks requiring real deployment/accounts. Generated metrics may update only the delimited README metrics block.

`docs/metrics/history.json` stores bounded GitHub metadata/traffic snapshots; it is not a replacement for the append-only source-update ledger. Never store session files, pairing codes, credentials, WhatsApp message contents, IP addresses, or private payment details in either history file.
